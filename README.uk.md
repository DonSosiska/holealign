# Holealign

Ліцензія: [PolyForm Noncommercial 1.0.0](LICENSE) (source-available, не відкритий код)

[English](README.md) | Українська

> Назва походить від моделі швейцарського сиру: кожен шар захисту має дірки, а інцидент стається
> лише тоді, коли дірки в усіх шарах співпадають. Вразливий пакет — одна дірка, увімкнена функція —
> друга, відкрита конфігурація — третя. Holealign показує, коли вони вишиковуються в одну лінію.

Holealign знаходить вразливості на Linux-хостах і визначає, чи вони **справді експлуатовані за
конфігурації саме цього хоста**. Агенти на ваших хостах надсилають на центральний сервер перелік
програмного забезпечення (SBOM) і набір фактів про конфігурацію. Сервер зіставляє вразливості через
Grype (разом із даними CISA KEV та EPSS), перевіряє CEL-правила на фактах і сповіщає кімнати
Matrix/Element, обрані за мітками хостів. Це один бінарний файл і один файл SQLite, без зовнішньої бази
даних.

Документація англійською; ця сторінка є перекладом [README.md](README.md). Якщо переклад і оригінал
розходяться, діє англійський текст.

## Проблема

Сканер, що порівнює версії пакетів із даними про вразливості, видає сотні знахідок на хост, і більшість
із них неможливо експлуатувати там, де вони працюють: вразлива функція вимкнена, порт не відкритий,
інша libc. Команди або тонуть у списку, або перестають його читати, і єдина важлива знахідка губиться
серед решти.

## Чим Holealign відрізняється

Holealign додатково читає сам хост. regreSSHion (CVE-2024-6387) експлуатований лише в системах із glibc,
де `LoginGraceTime` не дорівнює `0`. На хості з musl або з `LoginGraceTime 0` знахідку записано як
`affected_not_exploitable`, і нікого не будять сповіщенням. Коли Holealign не може визначити (немає
правила або бракує факту), вердикт `conditions_unknown`, а ніколи не «безпечно». Правила, яких ще немає,
може чернеткою написати LLM; чернетка залишається неактивною й ніколи не знижує вердикт, доки її не
схвалить людина.

```
 хост: збирач (root, без мережі) -> відправник -- HTTPS, лише вихідні --> сервер
                                                                           |
        SBOM (Syft)  +  факти (sshd -T, nginx -T, sysctl, сокети, ...)     |
                                                                           v
   Grype + KEV + EPSS  ->  правила (CEL) на фактах цього хоста  ->  вердикт  ->  вебінтерфейс + Matrix
```

| Вердикт | Значення |
|---|---|
| `exploitable` | Пакет вразливий, і умови правила на цьому хості виконуються. Надсилається сповіщення. |
| `affected_not_exploitable` | Пакет вразливий, але умови не виконуються або вразливість пом'якшено. |
| `conditions_unknown` | Немає правила, або бракує потрібного факту, або правило не вдалося обчислити. |
| `not_affected` | Правило каже, що пакет узагалі не зачеплений. |
| `resolved` | Знахідка зникла (пакет оновлено або видалено). |

## Можливості

- Агент із розділенням привілеїв: збирач (collector) від імені root без доступу до мережі та
  непривілейований відправник (sender), який є єдиним процесом, що розмовляє із сервером.
- Інвентаризація хоста та образів контейнерів (Syft), пакети ОС і мов програмування.
- Зіставлення вразливостей через Grype; KEV і EPSS показуються й використовуються для впорядкування та
  сповіщень.
- Факти про конфігурацію: sshd, nginx, Apache, PHP, sysctl і модулі ядра, сокети, що слухають, служби,
  контейнери Docker та обмежені читання `file.match`. Каталог: [docs/rules.md](docs/rules.md#fact-catalog).
- CEL-правила, вісім постачаються разом із системою. Вердикти та захист від чернеток:
  [docs/rules.md](docs/rules.md).
- Необов'язкова підписана центральна стрічка правил (ed25519, атомарна перевірка, імпорт без мережі):
  [docs/rules-feed.md](docs/rules-feed.md).
- Необов'язкове створення чернеток правил через LLM (Anthropic або будь-яка OpenAI-сумісна точка доступу,
  наприклад Ollama): [docs/llm.md](docs/llm.md).
- Сповіщення в Matrix/Element, що маршрутизуються за мітками хостів, із дедуплікацією, групуванням і
  зведеннями при сплесках: [docs/notifications.md](docs/notifications.md).
- Вебінтерфейс адміністратора: хости, знахідки, згруповані за CVE, з розподілом на «потребує уваги» та
  «фон», перевірка правил, токени реєстрації, маршрути Matrix, користувачі:
  [docs/user-guide.md](docs/user-guide.md).
- Сповіщення про стан системи: мовчазні агенти, застаріла база вразливостей, збій конвеєра.
- Режим без агента (сервер стежить за власним хостом): [docs/installation.md](docs/installation.md#agentless-mode).
- Підписані релізи: підписи cosign, SBOM, походження збірки (provenance).

## Архітектура

```
  Хост Linux, що моніториться (будь-яка кількість)  Сервер Holealign
 +-------------------------------------+        +----------------------------------------+
 | holealign-collector (root, БЕЗ мережі)|        | API агентів :8080 /api/v1/* /healthz   |
 |   sshd -T, nginx -T, sysctl, /proc, |        |   enroll, check-in, inventory          |
 |   сканування Syft, file.match       |        |                                        |
 |        |  unix-сокет                | HTTPS  | SQLite + база Grype    (data_dir)      |
 | holealign-agent sender (користувач   |------->| конвеєр: Grype -> CEL-правила -> вердикт|
 |   "holealign", єдиний із доступом    | push,  |                                        |
 |   до мережі)                        | лише   | адмінка    :8081 (за замовч. loopback) |
 +-------------------------------------+ вихід. |        ^  SSH-тунель / VPN / проксі    |
   жодного вхідного з'єднання до хоста  з'єдн. |        |                               |
                                                | сповіщувач Matrix ---> кімнати Matrix  |
                                                | LLM-автор (необов'язково) ---> LLM API |
                                                +----------------------------------------+
```

Подробиці: [docs/architecture.md](docs/architecture.md).

## Вимоги

- Хости, що моніторяться: Linux на amd64 або arm64 із systemd (для встановлювача та пакетів) і базою
  пакетів ОС, яку розуміють Syft і Grype (dpkg, rpm, apk).
- Сервер: Docker із Compose (образ контейнера) або хост Linux із systemd (`.deb`, `.rpm` чи бінарний
  файл). У постачуваних файлі Compose та unit-файлі systemd йому виділено близько 4 ГіБ пам'яті, а під
  час першого запуску завантажується база Grype (близько 100 МБ).
- Необов'язково: домашній сервер Matrix і обліковий запис бота для сповіщень; API LLM для створення
  чернеток правил.
- Збірка з вихідного коду: Go 1.27.4 (див. `go.mod`). Див. [docs/development.md](docs/development.md).

## Швидкий старт

Повний шлях на 15 хвилин (сервер без агента, перші знахідки, сповіщення в Matrix, перший віддалений
агент) описано в [docs/quickstart.md](docs/quickstart.md). Коротко, щоб спробувати сервер і один агент:

```sh
git clone https://github.com/DonSosiska/holealign.git
cd holealign/deploy
cp server.env.example .env       # задайте HOLEALIGN_ADMIN_PASSWORD (щонайменше 12 символів)
docker compose up -d --build
docker compose exec holealign-server holealign-server token create first -labels prod,web -max-hosts 5 -expires 72h
```

Агенти вимагають `https://`: поставте TLS перед портом 8080 ([варіанти TLS](docs/installation.md#tls)).
Потім на хості, що моніториться, від імені root візьміть `install.sh` з **тега релізу** (не з `main`),
прочитайте його й запустіть, передавши токен через файл:

```sh
V=X.Y.Z    # версія релізу зі сторінки https://github.com/DonSosiska/holealign/releases
curl --proto '=https' --tlsv1.2 -fsSLO https://raw.githubusercontent.com/DonSosiska/holealign/v$V/deploy/install.sh
less install.sh
sudo sh install.sh --version $V --server https://holealign.example.com --token-file /root/holealign.token
```

Встановлювач перевіряє підпис релізу через [cosign](https://docs.sigstore.dev/cosign/system_config/installation/)
і ставить збирач та агент як служби systemd. Адмінка слухає лише loopback: відкрийте її через SSH-тунель,
`ssh -L 8081:127.0.0.1:8081 you@docker-host`, за адресою <http://127.0.0.1:8081> і увійдіть як `admin`.
Щоб стежити за власним хостом сервера без окремого агента, див.
[режим без агента](docs/installation.md#agentless-mode).

## Підсумок безпеки

- **Жодних віддалених команд.** Агент ніколи не виконує нічого, що надіслав сервер. Кожна команда є
  жорстко заданим argv без оболонки; сервер може лише попросити читання `file.match`.
- **Розділення привілеїв.** Збирач від імені root не має мережі; відправник із мережею не є root. Помилка
  в парсері не може дістатися до мережі.
- **Агент не довіряє серверові.** TLS 1.2+, ланцюжок завжди перевіряється, довіра лише до приватного ЦС
  (`ca_file`), прив'язка SPKI та mTLS.
- **Обмежені читання файлів.** `file.match` читає лише файли, доступні всім на читання, у кількох
  каталогах конфігурації, за чорним списком, і маскує секрети, перш ніж щось залишить хост.
- **Хешовані секрети, обмеження частоти, захист повторної реєстрації.** Токени реєстрації та ключі агентів
  зберігаються як хеші SHA-256; зареєстрований хост не можна тихо зареєструвати повторно.
- **Вивід LLM неактивний, доки його не схвалить людина.** Чернетка ніколи не може знизити вердикт, а
  схвалення вимагає пароля рецензента.
- **Підписані релізи.** Keyless-підписи cosign із точною ідентичністю, SBOM, provenance.

Повна модель і контрольний список оператора: [docs/security-model.md](docs/security-model.md). Про
вразливості повідомляйте приватно: [SECURITY.md](SECURITY.md). Щоб перевірити реліз вручну (cosign,
`gh attestation`, образ сервера), див. [docs/installation.md](docs/installation.md#verifying-releases).

## Пакети та збірка з вихідного коду

Архіви релізів, пакети `.deb`/`.rpm` і образ сервера `ghcr.io/donsosiska/holealign-server` публікуються
з тегів `v*`. `make build` збирає бінарні файли в `bin/`; `make docker` збирає образ сервера з вихідного
коду. Див. [docs/development.md](docs/development.md).
